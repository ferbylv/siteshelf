# SiteShelf 页架

把正在看的网页保藏到本机，并用 AI 生成一句中文摘要、主分类和标签。v2 另含**本机加密保险库**：在你确认后保存登录信息，并仅在源站（主机名+协议+端口）完全匹配时填充。v2.1 增加导入导出、自定义分类、密码强度，以及 Prompt API 的输出语言声明。

## v2 范围

- 书签（v1）：工具栏保藏、侧边栏页架、公开元数据 + 可选 AI 分类
- 保险库（v2，独立数据域）：
  - 首次使用设置主密码（至少 10 位）。只保存随机盐和用派生密钥包裹的数据密钥，**不保存主密码或裸密钥**
  - 解锁状态只存在浏览器会话内存（`chrome.storage.session`）。服务工作线程被回收后，若会话仍在则自动恢复；否则需重新解锁。可选闲置锁定
  - 在普通登录页检测到用户名 + 密码表单。提交或按 Enter 时立刻把待保存登录写入**当前标签页**的会话存储（不等待 UI）。若该源站（主机名+协议+端口；默认 80/443 与省略端口等同）在保险库中已有任意登录，则**不再提示保存**（含不同用户名；其他账号请在侧边栏手动添加）。新站点会在页面右上角出现约 360px 的紧凑提示卡询问「保存到页架？」，必须点确认，**不会静默保存**。登录后跳转到其他主机时，**同一标签页**仍会显示该提示；写入的来源仍是捕获时的登录页，不会泄漏到其他标签
  - 下次访问**同一源站**（主机名+协议+端口；默认 80/443 与省略端口等同）时，解锁后可填充。`github.com` 不会填充 `gist.github.com`；`evil.com` 不会填充 `a.evil.com`；https 记录不会填充 http 页面；`http://192.168.1.1:8080` 不会填充 `:3000`。不用 eTLD+1、子串或模糊匹配
  - 优先在你点击扩展或页内按钮后填充。仅当已解锁、源站精确匹配、且只有一条登录时，才允许页面加载后自动填充；多条则弹出选择，不会猜测
  - 侧边栏「保险库」可搜索、复制用户名、显式显示密码、编辑、删除
  - 可更改主密码（会轮换数据密钥并重新加密全部记录）、可随时锁定
  - 主密码错误时直接失败，只提示重试，没有剩余次数一类的提示

## v2.1

- **保藏后可选写入保险库：** 保藏成功后（弹窗）以及侧边栏编辑条目时，可手动填写用户名和密码，点「保存到保险库」。未设置主密码会提示先去保险库设置；已锁定会提示先解锁。不会静默保存，也不会把这些字段发给分类引擎。
- **自定义分类：** 内置分类仍是默认值。可新增 1–12 字的分类名，保存在 `chrome.storage.local` 的 `siteshelf.categories`。删除自定义分类时，使用该分类的保藏会改记为「其他」。不能删除内置名。「全部」「未分类」不可作为自定义名。AI 分类会读取当前分类列表（含用户自建），并优先选最具体的一项；失败时仍记为「未分类」。
- **页架导入导出（侧边栏页架工具栏）：**
  - 导出 JSON：`{ kind: "siteshelf-bookmarks", version: 1, exportedAt, categories, bookmarks }`。只含书签与用户分类，不含任何密码。
  - 导入同一格式；若缺少 `kind`，也接受书签对象数组。按 `normalizedUrl` 合并，网址已存在则保留原 id。跳过浏览器内部页等受限地址。即使文件里带了 password 字段也不会写入书签库。
- **保险库导入导出（侧边栏保险库，需已解锁；加密恢复也可在未解锁/未设置时进行）：**
  - **加密备份** `kind: "siteshelf-vault-backup"`：导出 IndexedDB 中的 meta（盐、迭代次数、wrappedDek）与密文记录（ArrayBuffer 为 base64）。文件是密文，不含明文密码。导入为**整库替换**，之后必须用**备份时的主密码**解锁。若当前已解锁且主密码不同，导入后会锁定。
  - **Bitwarden 未加密 JSON**（会先警告文件含明文密码）：`encrypted: false`，`items[].type === 1` 的 login，读取 `login.username` / `login.password` / `login.uris[].uri`。`encrypted: true` 会提示「请导出未加密的 JSON」。卡片/安全笔记/身份会跳过。空密码跳过。导入时经 `saveLogin` 按主机+协议+用户名合并。
  - **CSV：** Bitwarden（`login_uri,login_username,login_password`）、Chrome/Edge（`name,url,username,password`）、Firefox（`url,username,password`）。自行解析引号字段。空密码跳过。
- **密码强度：** 0–4 对应 过短 / 弱 / 一般 / 较好 / 强。主密码仍至少 10 位，且分数需 ≥ 2（一般）。登录密码只显示强度、不阻止保存。
- **Prompt API：** `availability()` 与 `create()` 均传入 `expectedInputs` / `expectedOutputs`（`languages: ['en']`），以消除 Chrome「未指定输出语言」警告。提示词仍为中文；该选项不会强制模型用英文回答。

## 威胁模型（摘要）

- 登录记录用 AES-256-GCM 加密后写入独立 IndexedDB（`siteshelf-vault`），与书签库 `siteshelf` 分开。书签代码不会读取保险库明文
- 主密码经 PBKDF2-HMAC-SHA-256（当前 OWASP 建议 600,000 次迭代）派生包装密钥，再包裹随机数据密钥。主密码和裸密钥都不落盘
- 填充只发生在已解锁、且当前页主机名 + 协议 + 端口（origin；默认 80/443 与省略等同）与记录完全一致时。凭证只写入你确认的登录表单，不会发给 AI、日志或分析接口
- 扩展页面（弹窗 / 侧边栏 / 选项）才会询问主密码，网页内覆盖层**从不**收集主密码
- **主密码无法找回。** 忘记后无法解密已保存的登录，只能丢弃保险库数据

## 环境

请先安装依赖，再运行构建。scripts 见 package.json：dev、build、zip、compile。构建产物在 `.output/chrome-mv3`。

## 在浏览器中加载

1. 先完成本地构建
2. 打开 chrome://extensions 并启用开发者模式
3. 选择加载已解压的扩展程序
4. 指向产物目录 `.output/chrome-mv3`

完整路径示例：`/path/to/siteshelf/.output/chrome-mv3`

加载成功后，工具栏会出现「页架」。打开任意普通网页，点击图标即可保藏。侧边栏可从弹窗中的「打开页架」进入。保险库在弹窗 / 侧边栏的「保险库」标签中。

## 如何测试保存与填充

1. 首次打开「保险库」，设置至少 10 位且强度为「一般」以上的主密码（请用测试密码，不要用真实主密码做演示）
2. 打开一个 **https** 登录页（可用自己的测试站点）。在用户名和密码框填写测试值并提交
3. 页内**右上角紧凑提示卡**应出现「保存到页架？」：展示来源、用户名和掩码密码（约 320–380px，非全宽顶栏）。点「保存」。不要期待静默写入。工具栏图标上会出现角标。若该网站（精确主机+协议+端口，origin）已在保险库中，提交后**不应**再出现保存提示或角标；`github.com` 已保存时，`gist.github.com` 或 `http://github.com` 仍应提示；`:8080` 已保存时，同 IP 的 `:3000` 仍应提示
4. **跳转登录：** 在标签页 A 打开登录页并提交，站点跳到另一主机（例如 `https://login.example.com` → `https://app.example.com`）。落地页右上角仍应出现保存提示，且来源仍是登录页 `login.example.com`，而不是落地页。另开标签页 B 访问任意站点，**不应**出现该提示，角标也不应在 B 上亮起。点「保存」后，保险库记录的主机是捕获时的登录主机
5. 锁定保险库后再访问同一主机：应看到「解锁页架以填充」，输入主密码后才能填充。未确认的待保存项仍可通过弹窗「保险库」提示条保存，不会自动写入
6. 解锁后再次打开该主机：若只有一条匹配，可自动填充；点右下角按钮也可手动填充。多条登录必须手选
7. 用不同主机验证否定路径：例如保存 `https://github.com` 后，`https://gist.github.com` 或 `http://github.com` 都不应填充。保存 `http://127.0.0.1:3000` 后，`http://127.0.0.1` 或 `:80` 都不应填充；`https://example.com` 与 `:443` 应视为同一源站
8. 在侧边栏保险库搜索该条，复制用户名、点「显示密码」才应看到明文，删除需二次确认
9. 书签流程应仍可用：保藏当前页、侧边栏「页架」列表（可手动粘贴网址添加）、编辑分类
10. 保藏后在弹窗填写用户名/密码并点「保存到保险库」（需已解锁）。侧边栏编辑条目同样可以。不填则只保藏网页。
11. 侧边栏页架：导出 JSON 后再导入，同一网址应合并而非重复；自定义分类应一并带上
12. 侧边栏保险库（解锁后）：导出加密备份，锁定后用「从加密备份恢复」替换，再用备份主密码解锁。导出未加密 JSON 前应看到明文密码警告。导入 Bitwarden JSON / Chrome CSV 应出现对应登录
13. 新增一个自定义分类并保藏一页，确认 AI（若可用）能把该分类列入候选

本地自检脚本（不启动浏览器）：

```
bun run compile && bun run verify:vault && bun run verify:imex && bun run build
```

## AI 如何工作

分类只发送公开元数据（网址、标题、描述、短摘录），**不会发送页面上的表单值、用户名或密码。** 保险库与分类引擎没有数据通路。

### 1. Chrome Prompt API（优先）

Chrome 138+ 在满足设备要求时可使用内置 LanguageModel（Gemini Nano）：

- 桌面 Chrome（Windows / macOS / Linux / 符合条件的 ChromeOS）
- 需要足够磁盘与内存；模型会在首次使用时下载
- 当前官方语言覆盖以 en / ja / es / de / fr 为主，中文摘要可能不稳定。若效果不好，改用兼容接口
- 扩展会在 `availability()` 和 `create()` 中声明 `expectedOutputs.languages: ['en']`，避免控制台警告。这**不会**把摘要改成英文，系统/用户提示仍是中文。

默认设置为「自动」：先试 Prompt API，不可用再走兼容接口。分类只使用公开的网址、标题、描述和摘录。

### 2. OpenAI 兼容接口（后备）

在弹窗底部「AI 设置」，或右键扩展图标打开选项页：

- 分类引擎：自动 / 仅 Prompt API / 仅兼容接口
- 接口地址：例如 https://api.openai.com/v1（会请求该地址下的 chat/completions）
- 模型名：例如 gpt-4o-mini
- 密钥：只保存在本机 chrome.storage.local

密钥只会发往你填写的地址。扩展没有云端账号。

若两种引擎都失败，仍然会保藏该页，分类记为「未分类」，之后可手改。

同一规范化网址再次保藏会就地更新，不会产生重复条目。

## 权限说明

- storage：保存 AI 设置、保险库闲置锁定等非密钥配置。解锁后的数据密钥只放在 session 存储
- activeTab 与 scripting：点击扩展时读取当前页公开元数据（书签保藏）
- tabs：读取当前标签标题与地址，并从页架打开链接
- 主机权限 `https://*/*`、`http://*/*`：在普通网页注入内容脚本，用于检测登录表单、询问保存、按精确源站（主机名+协议+端口）填充。系统页与扩展商店仍无法注入
- sidePanel：侧边栏（由 WXT 根据 sidepanel 入口自动加入）

未申请 nativeMessaging、debugger、clipboardRead、webRequestBlocking。

## 技术栈

WXT + React + TypeScript，Manifest V3。保险库使用 Web Crypto：AES-256-GCM + PBKDF2-SHA-256（600,000 次）。
